# Java. Лабораторная работа №2: Создание собственной реляционной БД

Была проведена работа по созданию собственной реляционной СУБД на основе считывания и записи бинарных файлов с помощью встроенного класса `RandomAccessFile`.
Работа программы построена на цепочке из основных самописных классов, представленной ниже.


---


## Предметная область и схема данных

В качестве демонстрационной модели данных в проекте реализована предметная область **учета студентов и учебных групп**. 

### Таблица `Students` (Студенты)
Хранит персональные и академические данные учащихся:
* `student_id : int` *(Главный ключ)* — уникальный идентификатор студента.
* `full_name : String (char[100])` — ФИО студента, сериализуемое в массив символов фиксированной длины (100 символов).
* `group_id : int` *(Внешний ключ)* — внешний ключ, ссылающийся на идентификатор учебной группы в таблице `Group`.
* `birth_date : Date (long)` — дата рождения, хранящаяся в бинарном виде как числовая метка времени (`timestamp` в формате `long`).
* `avg_score : Double` — средний балл успеваемости.
* `is_budget : Boolean` — флаг формы обучения (`true` — бюджет, `false` — на платной основе).

### Таблица `Group` (Учебные группы)
Таблица групп студентов, связанная с таблицей студентов отношением `1:N` через поле `group_id`:
* `group_id : int` *(Primary Key)* — уникальный идентификатор учебной группы.
* `group_name : String (char[20])` — шифр/название группы фиксированной длины (20 символов, например, `"ИВТ-21"`).
* `group_year : int` — год набора / курс обучения.

### Описание основных компонентов

* **`DatabaseGUI`** — реализация графического интерфейса на базе Java Swing. Предоставляет окно для ввода SQL-запросов и отображает результаты выборки в удобном табличном формате. При некорректном вводе команд или внутренних ошибках выполнения предусмотрен перехват исключений с выводом сообщения об ошибке пользователю.
* **`SQLParser`** — парсер пользовательского ввода в структурированный SQL-запрос и последующий набор инструкций для менеджера таблиц. Реализованы базовые команды, предусмотренные техническим заданием (см. раздел «Инструкция пользователя»). Более сложные операции (такие как `JOIN` или каскадное изменение данных в связанных таблицах) в рамках данной работы не реализовывались.
* **`DatabaseManager`** — менеджер баз данных, отвечающий за хранение таблиц в оперативной памяти и маршрутизацию команд от парсера к соответствующим таблицам. Создает бинарные файлы для каждой новой таблицы и обрабатывает исключения, возникающие при выполнении операций на уровне хранилища.
* **`DataTable`** — ключевой класс таблицы БД, отвечающий за низкоуровневое управление бинарным файлом (`RandomAccessFile`), логическое удаление записей (`Soft-Delete`) и оптимизацию поиска с помощью индексов в памяти (`HashMap` и `TreeMap`).
* **`Record` и `Column`** — вспомогательные модели строк и столбцов для структурированного хранения, сериализации и передачи данных между таблицей и менеджером БД.

## Создание таблиц

Для примеров используются две таблицы — `groups` и `students`. Поля таблицы студентов позволяют продемонстрировать все поддерживаемые типы данных.

### 1. Создание таблицы групп
```sql
CREATE TABLE groups (
    id INT PRIMARY KEY,
    name STRING(40)
);
```

### 2. Создание таблицы студентов
```sql
CREATE TABLE students (
    id INT PRIMARY KEY,
    full_name STRING(200),
    birth_date DATE,
    average_grade DOUBLE,
    active BOOLEAN,
    group_id INT REFERENCES groups(id)
);
```

> **Важно:** Поле `group_id` указывает на идентификатор группы из таблицы `groups`. Попытка добавить студента с не существующим `group_id` приведет к ошибке.

## Добавление данных (INSERT)

### Добавление групп
```sql
INSERT INTO groups VALUES
(1, 'КНТ1'),
(2, 'КНТ2'),
(3, 'КНТ3'),
(4, 'КНТ4'),
(5, 'КНТ5'),
(6, 'КНТ6'),
(7, 'ТИДИ');
```

Проверить список созданных групп:
```sql
SELECT * FROM groups;
```

### Добавление студентов

**Добавление одной записи со всеми полями:**
```sql
INSERT INTO students VALUES
(1, 'Иванов Иван Иванович', '2005-03-15', 4.5, TRUE, 1);
```

**Добавление нескольких записей:**
```sql
INSERT INTO students VALUES
(2, 'Петрова Анна Сергеевна', '2006-07-21', 4.8, TRUE, 2),
(3, 'Смирнов Алексей Олегович', '2005-11-02', 3.9, TRUE, 7);
```

**Добавление записи с частичным набором полей:**
```sql
INSERT INTO students (id, full_name, group_id) VALUES
(4, 'Соколова Мария Андреевна', 1);
```

> **Примечание:** Пропущенные поля автоматически заполняются значением `NULL`. Первичный ключ (`id`) обязателен для заполнения и должен быть уникальным.

## Просмотр и поиск данных (SELECT)

* **Все студенты:**
  ```sql
  SELECT * FROM students;
  ```

* **ФИО и средние оценки:**
  ```sql
  SELECT full_name, average_grade FROM students;
  ```

* **Студенты группы КНТ1 (`group_id = 1`):**
  ```sql
  SELECT * FROM students WHERE group_id = 1;
  ```

* **Студенты группы ТИДИ (`group_id = 7`):**
  ```sql
  SELECT * FROM students WHERE group_id = 7;
  ```

* **Студенты со средним баллом не ниже 4.5:**
  ```sql
  SELECT full_name, average_grade
  FROM students
  WHERE average_grade >= 4.5;
  ```

* **Поиск по ФИО:**
  ```sql
  SELECT * FROM students
  WHERE full_name = 'Иванов Иван Иванович';
  ```

* **Поиск активных студентов:**
  ```sql
  SELECT * FROM students WHERE active = TRUE;
  ```

> **Совет:** Если `id` группы неизвестен, сначала найдите его с помощью запроса:
> ```sql
> SELECT id FROM groups WHERE name = 'КНТ1';
> ```
> И затем используйте полученный `id` в запросе к таблице `students` (оператор `JOIN` в текущей версии не поддерживается).

## Обновление данных (UPDATE)

* **Изменить средний балл студента:**
  ```sql
  UPDATE students SET average_grade = 4.7 WHERE id = 1;
  ```

* **Перевести студента в другую группу:**
  ```sql
  UPDATE students SET group_id = 3 WHERE id = 1;
  ```

* **Изменить статус активности:**
  ```sql
  UPDATE students SET active = FALSE WHERE id = 3;
  ```

* **Очистить значение поля (установить `NULL`):**
  ```sql
  UPDATE students SET average_grade = NULL WHERE id = 4;
  ```

## Создание индексов (CREATE INDEX)

Для ускорения выполнения поисковых запросов можно создавать индексы:

* **Индекс по полю `group_id`:**
  ```sql
  CREATE INDEX idx_students_group ON students (group_id);
  ```
  После создания этот индекс автоматически задействуется при запросах вида `SELECT * FROM students WHERE group_id = 1;`.

* **Индекс по полю `full_name`:**
  ```sql
  CREATE INDEX idx_students_name ON students (full_name);
  ```

> **Примечание:** Первичные ключи (`PRIMARY KEY`) индексируются автоматически.

---

## Удаление данных (DELETE)

* **Удалить конкретного студента:**
  ```sql
  DELETE FROM students WHERE id = 4;
  ```

* **Удалить неактивных студентов:**
  ```sql
  DELETE FROM students WHERE active = FALSE;
  ```

* **Удаление группы:**
  Группу можно удалить только в том случае, если на неё не ссылается ни один студент.
  1. Проверьте состав группы:
     ```sql
     SELECT * FROM students WHERE group_id = 6;
     ```
  2. Если группа пуста, выполните удаление:
     ```sql
     DELETE FROM groups WHERE id = 6;
     ```

## Удаление таблиц (DROP TABLE)

Команда `DROP TABLE` полностью удаляет таблицу и все её данные. Из-за наличия внешних ключей сначала необходимо удалить таблиц-зависимый объект (`students`), а затем основную таблицу (`groups`):

```sql
DROP TABLE students;
DROP TABLE groups;
```

## Форматы данных и ограничения

### Поддерживаемые типы данных

| Тип | Пример | Описание |
| :--- | :--- | :--- |
| `INT`, `INTEGER` | `1` | Целое число |
| `DOUBLE`, `FLOAT` | `4.5` | Число с плавающей точкой (разделитель — точка) |
| `STRING`, `STRING(n)` | `'КНТ1'`, `'Иванов'` | Строки в одинарных кавычках |
| `DATE` | `'2005-03-15'` | Дата в формате `YYYY-MM-DD` |
| `BOOLEAN` | `TRUE`, `FALSE` | Логический тип |

### Системные ограничения
1. **Первичный ключ:** Первый столбец должен быть единственным первичным ключом типа `INT`. Его значение нельзя изменять с помощью `UPDATE`.
2. **Регистрозависимость:** Имена таблиц и столбцов записываются латиницей и **учитывают регистр**. Значения строк могут содержать кириллицу.
3. **Ограничения условий `WHERE`:**
   * Поддерживается только **одно** сравнение за раз.
   * Для чисел допускаются операторы: `=`, `>`, `>=`, `<`, `<=`.
   * Для `UPDATE` и `DELETE` наличие секции `WHERE` является **обязательным**.
4. **Неподдерживаемые конструкции:** `JOIN`, `AND`/`OR`, `ORDER BY`, `IS NULL`, `!=`, `<>`.
5. **Строковый размер:** Размер `STRING(n)` указывается в байтах UTF-8. Символы кириллицы занимают по 2 байта каждый.
6. **Транзакции:** Ошибка в поздней строке многострочного `INSERT` не отменяет уже вставленные ранее записи.

## Выводы

В ходе выполнения лабораторной работы была спроектирована и реализована собственная реляционная СУБД с бинарным форматом хранения данных. Применение коллекций вроде `HashMap` и `TreeMap` и реализация удаления через изменение флага isDeleted (`Soft-Delete`) позволило организовать эффективную и быструю работу с записями (удаление, вставку, обновление), избавив систему от необходимости полной перезаписи файлов при каждой модификации. В свою очередь, внедрение вторичных индексов в оперативной памяти существенно сократило время выполнения поисковых запросов.

Таким образом, пользователю дана возможность проводить все нужные операции за константное время (`O(1)`), жертвуя памятью и загрузкой данных в оперативную память (при входе и выходе из программы - `O(N)`).
Такая реализация практически применима в заданной предметной области и может помочь в реальных задачах, требующих использования реляционных БД.
